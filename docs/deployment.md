# Cloudflare Pages

Canonical URL: https://ai-model-picker.pages.dev/

The `ai-model-picker` Pages project uses Direct Upload and the `main` production branch. It is accessible without sign-in. The deployment contains the compiled app, the public benchmark and guide data, the records file `core.json`, the static search index and a dated, metadata-only HN snapshot. It does not expose the local controller or classifier. The practitioners' named records, the article catalog and the restricted benchmarks are served only by Pages Functions, to granted accounts.

Benchmarks whose source terms do not allow republishing are not in the public bundle or in Git, and the public app does not mention them. Their records, sources, guide evidence and credits live in the ignored `.local/restricted/` directory: `research.json` holds the reviewed rows and `npm run data:build` writes `payload.json`. The `/api/restricted` Pages Function bundles `payload.json` and serves it to Google accounts the administrator has granted, using the `ai-model-picker-access` D1 database; the app adds the records before it renders. The dev and preview servers serve the same file locally. Deploying therefore needs `.local/restricted/payload.json`, as it needs the HN checkpoint. Keep a private backup of `.local/restricted/`. See [Google sign-in](../server/auth/README.md).

## Build and publish

The Pages Functions also need `.local/expert-articles/catalog.json`, the catalog of the practitioners' articles that person pages list. The Functions build bundles this file on the server. `GET` and `HEAD /api/expert-articles` use the same session and enabled-grant check as `/api/restricted`. Direct anonymous requests to the canonical origin receive `401`. A successful response uses `Cache-Control: private, no-store` and `Vary: Cookie`. A normal loopback `npm run dev` can read the local catalog. See [Article catalog](updating.md#article-catalog).

The practitioners' named records are served the same way, and only this way: they are behind sign-in because their summaries and job labels were written by a model review that has not been checked by hand (see [people pipeline](people-pipeline.md#privacy-and-what-stays-on-this-machine)). The Functions build bundles `build/records/named-private.json`, which `npm run records:build` (the first step of `npm run build:pages`) writes from `.local/people/`, so deploying needs `.local/people/` as it needs the restricted payload. `/api/named` returns the people, the review's notes and the use records; `/api/named/advice` returns method advice. Both answer `GET` and `HEAD` with the same session and enabled-grant check, `401` without a session or after a grant is revoked, and the same private, uncached headers. The Function serialises each part once when it starts, so a request only sends the prepared body. Measured on 23 November 2026, the compiled Functions bundle (`npx wrangler@4.163.0 pages functions build functions --outdir <folder outside the repository>`, which compiles locally and does not contact the account) was 10,104,002 bytes uncompressed and 1.8 MB gzipped, against Cloudflare's limit of 64 MiB uncompressed on every plan; loading it took 154 ms on this computer against the 1-second start-up limit. Rebuild and measure again if `named-private.json` grows several times over. The loopback dev server serves the same two parts from the build file.

The search index is static. `npm run build:pages` copies `build/records/search/` into `dist/search/`: a manifest, 256 word shards, fact files and record files of the measured records and Hacker News labels only (see [Search](search.md)). On 24 November 2026 it was 3,111 files and 57 MB, which made the whole upload 3,132 files against the 20,000 that Pages accepts on the Free plan; it grows by about one file per 32 new Hacker News comments. Search runs in the browser and makes no Function request. A D1 database behind a Pages Function was the approved alternative: with a local D1 on 24 November 2026, loading the index wrote 93,000 to 181,000 rows against the Free plan's 100,000 a day, and one search for a common word read up to 163,000 rows against 5 million a day for the whole account ([D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [Pages limits](https://developers.cloudflare.com/pages/platform/limits/), checked 24 November 2026). No search database or binding exists.

The step-by-step release, with the expected output of each command, is under [Publish](updating.md#publish) in Updating the data. In short:

```sh
npm test
npm run hn:test
npm run arxiv:test
npm run format
npm run format:check
npm run build:pages
npm run check:pages
npx wrangler@4.163.0 pages deploy dist --project-name ai-model-picker --branch main
```

`check:pages` reads `dist/` and stops the release if the comment files come from different exports, a file is over 25 MiB, a claim or story title still contains a link, an email address, a handle or a phone number, the build contains an identifier that exists only in the restricted results, the catalog file or an expert article link appears in static output, a named record, `named-private.json` or the name of anyone in `.local/people/people.json` appears outside the Hacker News comment files and the Hacker News claims and titles in the search index (public story titles and claims may name anyone), the name of a restricted benchmark appears outside the Hacker News comment text, it contains a path on this computer, an `arxiv-snapshot.json` from an older build is present, the build has more than 20,000 files, the search index is missing or mixes files from two builds, or a search for the index's commonest word would read more than 4 MiB before compression. It prints counts only, and needs `.local/people/people.json` and `.local/restricted/research.json` to read the names it looks for.

Run the deploy command from the repository root so Wrangler compiles `functions/`. It reads the ignored `wrangler.jsonc` (copied from `wrangler.example.jsonc`) for the `AUTH_DB` binding, `PUBLIC_URL` and `ADMIN_EMAIL`; that file is the source of truth for the project's bindings and variables. `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are Pages secrets set with `wrangler pages secret put`. Apply new files in `server/auth/migrations/` with `npx wrangler@4.163.0 d1 migrations apply ai-model-picker-access --remote` before deploying.

Authenticate the CLI through its existing login or an operator-managed environment. Do not put account identifiers or credentials in source, build output or command arguments. `wrangler whoami` prints the account's email address and `wrangler pages deployment list` an address that contains the account identifier; keep both out of commits, documents and messages. Confirm that the authenticated account contains the existing project before uploading. Upload only `dist/`, never the repository or `.local/` directory.

`build:pages` selects the published reader and exports a consistent SQLite snapshot after the frontend build. The exporter reads the current classifier and saved six-month window. `hn-snapshot.json` carries summary results, coverage counters and the number of comment files. The comment files, `hn-comments-1.json` onwards, carry the ID and valid assessments of every comment that has at least one, newest first, and load only when a view needs the comments. For a run made by the thread pipeline they also carry each comment's story ID, task, one-sentence claim, themes and preferences, and the first file carries the scrubbed titles of those stories. Matching revision identifiers prevent mixing releases. These files exclude comment bodies, account fields, local paths, classifier prompts, model weights and credentials. Generated snapshots remain in ignored build output.

Cloudflare Pages accepts at most 25 MiB for one file, so the export starts a new comment file at 12 MiB and the app reads the files together. It refuses to write more than 16. The run reviewed on 19 November 2026 exported 86,745 comments in four files, 38.5 MB in all, and was published that day. Extended the same evening, it exports 88,309 comments in four files, 39.1 MB in all, and was published again.

`build:pages` runs `npm run records:build` first and, last, `scripts/export-records-site.py`, which copies `build/records/core.json` to `dist/core.json` and `build/records/search/` to `dist/search/`. It stops if `core.json` holds a record that is not measured, if `core.json` and the exported comment files describe different collections (comment count or dates), or if the search index and `core.json` describe different records. Nothing from `.local/arxiv/` is exported: the Papers page and its `arxiv-snapshot.json` were removed on 24 November 2026, and `check:pages` fails if that file is present.

The local scan can continue during export. Hosted results remain at the displayed publication time until the next build and upload. They must not be presented as a live view of the computer's progress or as a complete six-month collection while processing remains incomplete. Local start/pause controls are absent from the hosted app.

Comment text, parents and replies load directly from the public HN Firebase API when requested, inside the reader. Text is validated, stripped of author fields and rendered as escaped text. Pages Functions run only for `/auth/*` and `/api/*`; static assets are served directly. Anonymous visitors make no Function requests, because the app checks the session only when the session's readable CSRF cookie is present. The hosted app needs no inference service. Cloudflare currently charges no usage fees for static asset requests; HN requests go from the browser to its public API. See [Pages pricing](https://developers.cloudflare.com/pages/functions/pricing/), checked 16 November 2026.

## CLI compatibility

The Cloudflare connector manages and verifies the project. The available `cf` v0.15.0 has no Pages upload command (and rejects the documented `cf cli search` command). The release therefore uses the documented [Wrangler Pages Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/) command for local assets. No Wrangler project configuration or migration is needed. Recheck `cf` support before changing this exception.

## Licences

The Data page's **Licences and attribution** section credits every source with its licence, required wording, changes made and the day its terms were checked (`src/lib/attribution.ts`). The build writes `third-party-licenses.txt` with the licence text of each bundled npm package; font licences are in `public/fonts/`. The JSON download holds the public snapshot, the measured records, the benchmark definitions, the job list and the attribution list; it excludes restricted results, practitioner records and OpenRouter usage, whose terms do not allow re-serving it as data. Recheck the terms before adding a source or changing what is published.

## Crawler exclusion

`public/robots.txt` disallows every path. `public/_headers` applies `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet` to every static response, including the JSON snapshots and deployment aliases. The HTML also includes the robots meta tag. All snapshot files, including every comment file, use `Cache-Control: no-store`.

These directives discourage compliant crawlers and indexing. They are not access control and cannot prevent determined scraping. A crawler blocked by robots.txt cannot read the noindex header; external links can still cause URL-only search listings. The app's selected access policy is public link access. See [Google's noindex guidance](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

## Release verification

`npm run check:pages` covers the build before upload. After upload, the live checks under [Publish](updating.md#5-check-the-live-site) compare the live Hacker News snapshot and search manifest with `dist/`, check that the live records file and a live search record file hold no practitioner record, that the four protected endpoints (`/api/restricted`, `/api/expert-articles`, `/api/named`, `/api/named/advice`) return 401 without a session, that `/arxiv-snapshot.json` is gone, and the headers of a comment file. In a browser, signed out, check Brief's chooser and a brief, a model page, Switch, a search, a Benchmark page, the App guide, the Data page (no scan controls) and People (the sign-in line only), and an old Board, Discussion and Papers link; confirm that the console has no errors and that no request goes to `/api/`, to `/auth/` or to a local address. Then, signed in with a granted account, confirm that the restricted benchmarks appear, People shows the matrix, a person page shows its records, method advice and articles, and the Named band shows cards on a brief. Only the owner can make that last check.
